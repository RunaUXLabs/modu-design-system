# Storybook 목적과 범위

## 보여주려는 것

이 Storybook은 디자인 시스템을 개별 컴포넌트 목록으로만 보여주지 않고, 공통 UI가 실제 서비스 화면에서 어떻게 조합되고 사용자 선택에 따라 어떻게 달라지는지 확인하기 위한 환경이다.

서비스 코드를 기준으로 토큰 → 컴포넌트 → 조합 → 화면의 연결을 보여준다. Figma의 콘텐츠 슬롯은 React children/props로 표현하며, 같은 컴포넌트의 콘텐츠나 사용 맥락이 달라진다는 이유로 새 variant를 추가하지 않는다.

## 확인할 수 있는 수준

| 영역 | 보여주는 내용 |
| --- | --- |
| Foundations | 실제 CSS 토큰의 값과 색상·타이포·간격 등의 적용 모습 |
| Atoms / Molecules | 공통 UI의 props, variants, 상태와 콘텐츠 구성 |
| Patterns / Bubble Composition | 회의 버블 안에서 안내·시간 카드·버튼·대기 현황을 조합하는 방식 |
| Patterns / Response Preview | 응답 카드의 선택값을 카드와 현황표에 함께 전달하는 방식 |
| Service Screens / Meeting States | 회의 생성·편집, 필참/선택 참석, 응답·수정, 마감, 확정, 실패 복구 화면 |
| Service Screens / Workbench | 계정·시간·리셋 조작에 따라 달라지는 서비스 화면과 상태 |

Controls는 컴포넌트 속성과 예제의 시작 상태를 살펴보는 데 사용한다. 화면 안의 클릭과 입력은 서비스 상태로 처리하므로 시작 Controls와 조작 이후 상태는 구분한다. Docs는 사용 규칙과 조합 근거를 연결하고, play 함수와 접근성 패널은 동작·접근성 검토를 돕는다.

## 재사용 UI와 서비스 기능의 경계

공개 컴포넌트·토큰·타입은 `src`에서 제공한다. 회의 상태를 해석하고 저장·마감 액션을 연결하는 코드는 `examples/service`의 서비스 스냅샷에 둔다. 화면 예제는 현재 패키지 컴포넌트를 사용하지만 서비스 기능 자체를 재사용 컴포넌트로 공개하지 않는다.

Field는 편집 UI를 children으로 받을 수 있지만 편집 상태와 저장 로직은 서비스가 관리한다. 응답 카드와 현황표도 전달받은 값을 표시하며 일정 확정 규칙을 소유하지 않는다. 이 구분을 통해 공통 UI를 바꾸는 일과 서비스 행동을 바꾸는 일을 구별할 수 있게 한다.

## 포함하지 않는 범위

- 모든 서비스 페이지나 외부 연동을 구현한 제품 전체 데모는 아니다. 캘린더 등록·회의룸 예약 문구는 실제 외부 API 연동을 보장하지 않는다.
- Storybook은 현재 소스를 렌더링한다. 배포 패키지를 설치한 소비 앱 검증이나 npm 발행을 대신하지 않는다.
- 서비스 예제는 동기화 시점의 스냅샷이며 원본 서비스와 자동 연동되지 않는다.
- 고정 phone 프레임은 기존 화면 맥락을 보존한다. 모든 화면 크기에 대응하는 제품 구현을 의미하지 않는다.
- 타입 검사·DOM 테스트·정적 빌드 통과는 전체 브라우저 play, WCAG 준수 또는 Figma 픽셀 일치 검증을 의미하지 않는다.

실행 방법은 [Storybook 가이드](storybook-guide.md), 현재 검증 결과와 소스 대응은 [동기화 기록](synchronization.md)을 참조한다.
